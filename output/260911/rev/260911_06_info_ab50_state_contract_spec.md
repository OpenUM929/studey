## 1. 범위와 효력
04 수리 명세 §2의 미확정 부분을 아래 후보 계약으로 구체화한다. 04 원문 및 05 판정은 보존한다. 근거: `260911_05_info_ab50_state_contract_ruling.md` §2 BF1. 이번은 명세 작성이지 독립 판정·코드 반영·배포 승인이 아니다.

선택한 후보는 **전역 미통과 유지 + 관측 통계 별도 표시**다. 자료가 불완전한 채 전역 PASS를 얻는 예외는 요청하지 않는다. 따라서 이 계약만으로 현재 배포 차단이 해소되지는 않는다. 원천 보완 또는 정확한 파서 수리로 결함이 해소되어야 하며, 실제 불완전 자료를 남기고 배포하려면 별도의 구체적인 정책 변경 두 키가 필요하다. 그 결정을 판정자에게 작성하도록 미루지 않는다.

## 2. 단계와 분모
아래 이름은 제안 보고서 필드이며 새 정본 코드/ID가 아니다. 각 값에는 source_path, source_hash, source_locator를 붙이고 미확인 값은 null로 보존한다. null을 0으로 바꾸지 않는다.

| 단계 | 검사 단위·분모 | 산출물 및 의미 |
|---|---|---|
| 입력 동결 | 원천 EX 디렉터리 집합과 transcript/meta 각각; 04 스냅숏과 현재 원천을 양방향 비교 | expected/observed/duplicates/missing/extra 및 파일 bytes/hash 불일치 전부. 현 스냅숏 60유닛/120파일은 승인 기준 상수가 아님 |
| 원천 완전성 검사 | 유닛별 인쇄 선택형 ID 집합과 추출 선택형 ID 집합; 서답형은 별도 집합. 선언 총수·열거 총수·추출 총수 각각 보존 | declared_selective_count, declared_descriptive_count, observed_item_ids, parsed_score_ids. 선언 수가 같아도 ID 누락/동수 대체는 FAIL. 인쇄 ID가 확인되지 않으면 완전성 BLOCKED |
| 관측 통계 | 확인된 선택형 배점의 고유 ID 집합만 관측 분모. 시험 전체 분모와 별도 출력 | 분모 종류를 observed로 표시; 부분 자료에는 완전 시험 평균·정식 Tier를 새로 부여하지 않음. 관측값이 있어도 원천 FAIL 유지 |
| 정식 통계 적격성 | 기존 승인된 통계 규칙의 대상 집합; 적격/비적용/부분/미확정 ID를 모두 출력 | 현재 집계를 임의로 재구성·제외하지 않는다. 아래 상태 라벨은 추가 정보이며 실제 정본 집계 변경은 Q1 정확한 diff 심사 전 금지 |
| 기준 재생성/검사 | 승인된 원천·계층 집합과 정본 값; 계층/연도/ALL 각각 대조 | 하위 실패와 경고를 전파. 관측 통계 성공을 정본 일치 성공으로 바꾸지 않음 |
| A/B 배포 | 원본 문제지에서 얻은 A와 B의 문항 ID 집합을 독립 결과와 각각 양방향 대조 | 통계 원천의 분모와 무관. 맹목 풀이·품질·N/V·난이도·수정 후 재검증·최종 승인 모두 충족해야 배포. 단순 50행은 증거 아님 |

분모 예: 05가 인용한 EX-social-20261M의 인쇄 24+3=27, 분류 완전9+부분11=20, 파싱 선택형 배점15는 서로 다른 집합이다. 이 숫자를 15/15 전체 통과나 20/27 배점 커버리지로 변환하지 않는다. 여기서는 선행 판정 인용이며 새 전사/집합 실측으로 주장하지 않는다. 실제 구현 검증에서는 각 ID 집합·근거를 다시 유도한다.

## 3. 상태별 실행 계약
**현행 유지:** 기존 명령의 종료 코드를 보고 그대로 보존한다. measure의 중복 후보 경고는 현행 코드에서 warning-only이며 이 명세가 기존 코드를 이미 exit1로 바꿨다고 주장하지 않는다. 명령 exit0이어도 WARN이 남으면 전체 수용은 실패다(CLAUDE.md 원칙11).
**변경 요청:** 향후 Q1 구현의 상위 계약 결과를 아래 0/1/2로 명시적으로 출력·전파한다. 기존 각 명령의 코드 외에 `contract_exit`를 기록하고, 규범 적용/코드 수정은 두 키 전에는 하지 않는다.

| 상태 | 관측 통계 | 정식 적격성 표시 | contract_exit | 잔여 FAIL/배포 |
|---|---|---|---:|---|
| 원천·ID·합계 완전, 적용 대상, 경고 없음 | 계산 가능 | eligible | 0 (해당 단계만) | 다른 단계 통과를 뜻하지 않음 |
| 선택형이 원천상 실제 비적용이며 근거 완비 | 선택형 통계 N/A | not-applicable | 0 (비적용 확인만) | 분모에 가상 0점/문항 추가 금지; 구조 난이도 등 별도 게이트 필요 |
| 선언/추출 불일치 또는 실제 부분 자료 | 출처 확인된 부분만 partial 표시 | partial; 전체 적격 아님 | 1 | 유닛 FAIL 및 전역 FAIL 유지; 배포 blocked |
| 합계축·선언·적용 여부 근거 미확인 | 확인된 값만 diagnostic | unresolved | 1 | 미확정 ID/근거 누락 목록 보존; 배포 blocked |
| 중복 후보 미해결 또는 기타 WARN | 현행 산출은 보존 | unresolved (후보를 자동 제외하지 않음) | 1 | 모든 WARN 원문 보존; 전역 성공 불가 |
| 역사적 부분 활용 허용 | 해당 판정·해당 유닛·해당 용도만 사용 | historical-permission 필드에 별도 기록 | 원천 상태가 1이면 그대로 1 | 과거 허용은 FAIL 해제·신규 배포 허가 아님 |
| 입력 누락/해시 drift/명령 실행 불가/출력 파싱 불가/검출력 fixture 실패 | 신뢰 가능한 통계 없음 | blocked | 2 | 계산/정본 반영 중단, 기존 산출을 신규 결과로 인용 금지 |

합성 규칙: 어느 필수 단계든 2이면 전체2, 그 외 1 또는 잔여 WARN/FAIL이 있으면 전체1, 모든 필수 단계가 완료되고 기대 출력·집합·카운트·WARN0을 충족할 때만 전체0. 미실행 필수 단계는 성공이 아니라2다. 하위 원 종료 코드와 stdout/stderr를 함께 기록하며 진단용 하위0이 상위1/2를 덮지 않는다. 정식 통계 적격성·역사 활용 여부는 Boolean PASS 하나로 압축하지 않는다.

## 4. 잔여 및 재검증 조건
- known duplicate, partial, uncovered/합계축 미확인은 각각 유닛ID·문항ID(확인 가능한 경우)·근거·원인 확정 여부·담당 권한·closure evidence를 기록한다. 새 상태 라벨로 기존 WARN을 INFO로 격하하지 않는다.
- 어떤 원천/파서 변경도 적용 전후 바이트와 ID 차이를 기록하고 전 모집단을 다시 검사한다. 원인 확정 전 전사자를 오류 소유자로 단정하지 않는다.
- 불완전 자료 자체가 지속되면 전역 FAIL을 계속 반환한다. 과목별 배포 예외를 이 계약에 암묵적으로 넣지 않는다.
- Q1 diff 검토에는 정상, 비적용, 부분, 선언/합계 불일치, 중복 후보, 역사 허용+FAIL, 원천 drift, 하위 실패/경고, 미실행, 계층 동수대체 사례와 예상 contract_exit를 제공한다. 이는 테스트 명세이며 실행 완료가 아니다.
- 승인 후 전체 모집단에 적용한 결과에는 전 유닛 상태와 잔여 목록이 필요하다. 이번 바이트 확인은 규칙 적용 결과가 아니다.
- 기준이 바뀌면 종전 판정은 stale. 원천 재생성·기존 세 게이트를 새로 실행하고, 정보 구조 난이도 서명 및 A/B 문항 독립 재검증 뒤 최종 배포 판정으로 간다.

## 5. 요청 결정 — 작성/판정 분리
- [ ] BF1 보완안의 적용 단계·분모·종료 코드·잔여·재검증 계약이 구현 후보를 준비할 만큼 구체적인지 독립 판정한다(approve/revise-required/reject).
- [ ] §3 contract_exit 추가/전파라는 정확한 변경 요청은 사용자 키와 별도 감사키 확인 대상으로 남긴다. 기존 배포 요청은 재질문하지 않으며 신규 계약의 명시 승인으로 확대하지 않는다.
Q1 코드·fixture·Q3 난이도 기준은 이번 승인 요청 밖이다. BF1 보완안을 수용해도 정확한 패치와 기준 재동결 없이 구현·배포할 수 없다.

## 검증 범위
이 문서는 소유자 보완안이다. 제품/기준 수정, 독립 감사, 신규 정책의 전수 적용, 회귀 테스트 실행은 수행하지 않았다. 보호 기준 세 파일과 선행 문서 보존 여부 및 04의 원천 스냅숏을 별도로 바이트 대조한다.
