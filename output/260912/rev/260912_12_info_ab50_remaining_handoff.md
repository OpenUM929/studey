## 5. 다음 라운드 실행과 보고 규칙

적용: `docs/ITEM_DELIVERY_WORKFLOW.md`, `docs/ASTRA_EXECUTION_POLICY.md`, `docs/SESSION_HANDOFF_GUIDE.md`.

1. 세트 전체 작성/수정→감사→지적 통합이 한 라운드다. revision1–4, 호출 수, 체크포인트를 라운드 수로 임의 환산하거나 번호를 초기화하지 않는다. 현재 기록만으로 완료된 전체 라운드 수를 확정하지 않는다.
2. 재개 시 이 문서와 연결 근거를 읽고, 소유권·파일 변경·실행 가능 여부만 한 번 확인한다. Q3 미확정 권한/근거를 단일 결정 묶음으로 닫는 것이 첫 작업이다. 승인된 Q1/B1–B3를 재작성하지 않는다.
3. 내용 수정은 A/B 전체 결함 목록 기준으로 묶고 수정→영향 범위 시험→실패 수정→재시험을 연속 수행한다. 단순 부분 완료 때 승인을 다시 묻거나 응답 종료로 실행을 끊지 않는다.
4. 독립 단계는 깨끗한 Astra 컨텍스트에서 순차 실행한다. 맹목 입력에 정답·해설·작성자 결론을 섞지 않는다. 실제 실행 불가이면 불가 조건만 기록하고 실행한 것으로 꾸미지 않는다.
5. 각 라운드 반환에는 **대상/입력 버전, 완료 ID·변경 ID, 실행 명령·종료코드·경고, 결함별 해결/잔여, 산출물 경로·해시, 실제 실행자·독립성, NEXT·소유자·중단 조건**을 반드시 함께 넣는다. 다음 실행자는 기록을 읽고 이어가며 완료분을 재작성하지 않는다.
6. 멈춤: 전체 완료, 사용자 중단, 실제 자원/권한/필수 입력 차단. 절차의 세 번째 전체 라운드에도 차단이 남으면 실패를 보존하고 관련 절차 원인을 한 번 정리한다. 시험 횟수만 늘리는 네 번째 루프로 숨기지 않는다.
