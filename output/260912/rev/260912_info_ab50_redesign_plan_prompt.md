# 1. 목표와 현재 위치

**A형 25문항·B형 25문항, 총 50문항 모두 기존 정보 자료의 최고 수준에 필수 사고력을 더한 문제로 완성한다.** 세트 평균이 아니라 각 문항의 요구다. 두 세트는 같은 목표 수준을 갖되 풀이 골격을 복제하지 않는다.

이 문서는 계획·복사 실행 프롬프트다. 문항 작성이나 독립 감사가 실행됐다는 증거가 아니다. 사용자 요청의 ‘다시 만들기’는 **기존 2라운드의 실질 재설계**로 처리한다. 기존 후보·자료·감사 이력을 삭제하거나 라운드 번호를 초기화하지 않는다.

현재 기준 증거:
- `output/260912/rev/260912_17_info_ab50_quality_return.md`: 감사 당시 50문항 중 최상위 미달 43, 미확인 7. 출력 일치 50/50은 품질 합격이 아니다.
- `analysis/wip/solve-back-verifier_260912_info_ab50_policy_key.md`: 이후 A6·A23·A25 조건, B3 실행 코드, 답지 유형 및 기존 문항 참조를 보완했다. 이미 수정한 것을 미수정이라고 반복 보고하지 않는다. 원천 근거 완비·난도 합격으로 확대하지도 않는다.
- 모든 문항의 필수 사고와 비교 근거는 재검토 대상이다. 미확인 7문항을 자동 합격시키지 않는다.

# 3. 실패를 반복하지 않는 설계 원칙

## 3.1 최단 풀이를 먼저 확인

각 문항은 작성 시 다음을 기존 설계표 또는 답지 내부 기록에 남긴다. 별도 점검 보고서를 문항마다 만들지 않는다.

`문항ID | 유형·비수치 변형 2축 | 최근접 기존 문항 | 목표 사고 | 최단 타당 풀이 | 필수 발상 | 우회 경로 | 원천 대비 차이 | 상태`

1. 답을 먼저 풀어 보고 가장 짧은 풀이를 적는다. 긴 모범해설의 문장 수·루프 회차를 독립 추론 단계로 세지 않는다.
2. 어떤 조건과 자료를 연결해야 답이 결정되는지 설명한다. 핵심 조건 하나를 제거했을 때 후보가 늘거나 결론이 달라지는지 확인해 실제 필요성을 검토한다. 모든 안전 조건까지 제거해야 한다는 뜻은 아니다.
3. 직접 대입, 작은 경우의 단순 열거, 선지 역대입, 발문에 제공된 반례·분기·공식만으로 핵심 추론을 건너뛸 수 있는지 공격한다. 검산용 프로그램의 전수 탐색과 학생의 필수 사고는 구분한다.
4. 기존 난도 기준의 실제 적용 근거를 적는다. **두 조건의 결합만으로 최고 난도가 되지 않는다.** 정형 2~3단계에 그치면 목표 미달로 재설계한다. 서답형 미서명 기준을 임의로 서명하거나 배점만으로 T4를 부여하지 않는다.

**금지:** 기존 코드 뒤에 ‘왜인지 설명’, ‘반례 하나’, ‘일반식 증명’을 붙인 사실만으로 사고력·신규성·최상위를 주장하는 것. 숫자·코드 길이·반복량·낯선 용어로 어렵게 보이게 하는 것. 답을 사실상 알려 주고 설명만 요구하는 것.

## 3.2 확장 전에 생성 방식 확인

첫 대표 문항을 문제·답·해설까지 작성한 즉시 위 자기검산을 한다. 쉬운 생성 방식이면 그 자리에서 고치고 같은 방식을 나머지에 복제하지 않는다. 이는 **작성 내부 점검**으로, 별도 독립 승인·사용자 확인·새 라운드를 만들지 않는다. 이미 작성된 세트의 전수 감사는 앞 문항 지적 때문에 중단하지 않는다.

## 3.3 두 세트의 역할과 중복 방지

- A·B 모두 같은 최고 목표. A를 기초, B를 심화로 나누지 않는다.
- 관측에서 초기 상태·조건을 복원하기, 여러 구현을 구별하는 시험 설계, 불변량과 경계의 결합, 제한된 정보로 수정안의 타당성을 결정하기 등은 **설계 후보**다. 그 이름 자체는 난도 증거가 아니다.
- 문항별 `(주어진 자료 · 요구 행동 · 풀이 골격 · 결정적 발상)`을 비교한다. 같은 풀이의 숫자·문자 교체를 A/B 대응 문항으로 만들지 않는다.
- 기존 감사의 A3/B14 회전 복원, A14/B17 최종 상태와 이력, B4/B20 요약 정보 손실 중첩을 우선 해소한다. 다만 이것만 검사하고 신규 중복을 놓치지 않는다.
- 25칸을 채우려고 쉬운 문항을 남기지 않는다. 미달 슬롯은 미완료로 명시하고 재설계한다. 검증된 유형·범위를 억지로 늘려 개수를 맞추지 않는다.

# 4. 실행 순서 — 기존 2라운드 계속

## 단계 A: 전수 재설계와 답지 동시 작성

1. 기존 WIP·현재 후보·감사17을 한 번 대조해 이미 고친 내용과 남은 내용을 구분한다.
2. 작업용 기대 ID는 A/1~25, B/1~25로 고정한다. 이는 기존 슬롯 추적명이지 새 정식 세트ID가 아니다.
3. 대표 문항의 생성 방식을 먼저 자기검산한 뒤 전수 재설계를 진행한다. 원래 쉬운 코드의 보존은 목표가 아니다. 승인 유형·범위 안에서 지문과 코드도 필요한 만큼 바꾼다.
4. 문항별 답·중간 상태/식·경우 누락 없음·구성형 대체 정답 조건·채점 항목을 함께 작성한다. 원천 위치와 기존 후보 위치를 구별한다.
5. 정답·조건 경계·최단 우회·필요 자료·배점 합을 검사한다. 유한 테스트는 일반 명제의 증명을 대체하지 않는다.

## 단계 B: 답안을 숨긴 독립 풀이 → 고정 후 품질감사

- 실제 Astra인 작성자와 분리된 깨끗한 컨텍스트에서 순차 수행한다. 모델 요청값과 실제 실행 증거를 구분한다.
- 처음에는 문제 전용 파일과 허용 참고자료만 전달한다. **답지·통합본·작성자의 최단 풀이/설계표·자기검산 스크립트·감사 결론은 금지 입력**이다.
- 독립 답안과 실제 사용한 최단 풀이를 먼저 저장·해시 고정한다. 그 뒤 답지·유형·원천·이전 세트·감사17을 열어 정답/해설/난도/신규성/채점을 비교한다.
- 기존 맹목 답안은 변경되지 않은 입력과 기준에만 재사용한다. 본문을 바꾼 문항에 과거 출력 검증을 승계하지 않는다. 전수 재설계라면 변경된 50문항이 새 풀이 대상이 된다.
- 실패 지적은 한 전수 표와 한 수정 목록으로 통합한다. 어려운 문항 몇 개만 확인하고 전체 합격으로 확대하지 않는다.

## 단계 C: 남은 결함 종결과 배포

2라운드 감사 후 남은 실제 내용 결함은 기존 **3라운드**에서 수정·영향 재검증한다. 통과한 버전은 보존하며 취향 수정으로 회귀를 만들지 않는다. 3라운드 이후 차단 결함은 숨기거나 라운드를 초기화하지 않고 기존 절차의 실패 처리 규정을 적용한다.

최종 판정은 작성·감사와 분리된 Astra 컨텍스트가 수행한다. 같은 제품을 작성한 주체가 자기 승인하지 않는다. 유효한 최종 판정 뒤 조정자가 동일 통합본에서 문제지·답지/해설을 파생하고 인덱스·감사 이력을 동기화한다.

# 6. 실행 자원·인계 제약

- 한 번에 한 독립 단계만 실행한다. 대량 병렬 팀이나 Sol 대체를 자동 도입하지 않는다.
- 네이티브 역할은 설치된 적절한 역할을 사용하고 `.claude/agents` 파일은 책임 정의로 읽는다. Claude Code 역할을 실제 실행했다고 가장하지 않는다.
- 위임 전 정확한 단위 ID·파일 수/크기·읽기 허용/금지·출력 소유자·모델/깊이·남은 예산 측정·종료 조건을 기존 WIP에 기록한다. 측정 불가는 충분함으로 간주하지 않고 AGENTS의 직접 수행/단일 유계 단위 대안을 적용한다. 독립 검토는 작성자의 직접 자기검산으로 대체할 수 없다.
- 원장과 제품은 조정자 단독 소유. 감사자는 배정된 보고서만 기록하거나 읽기 전용 반환을 한다. 다른 작성자의 제품을 고치지 않는다.
- 실제 제한 실패가 나면 완료분·해시·정확한 NEXT를 보존한다. 불확실한 시각까지 장시간 sleep, 재시도 분산, 모델 변경, 복구 보장 없는 완료 시각 약속 금지.
- 실행 가능하면 계속한다. 중간 보고·일부 수정·지침 확인만 하고 ‘진행하겠다’는 최종 응답으로 멈추지 않는다. 실제 작업 종료/사용자 중단/필수 권한·입력·자원 차단만 종료 사유다.

기존 코드에 반례/증명 질문만 붙였던 실패 방식을 반복하지 마라.
두 조건의 결합도 그 자체로 최고 난도 증거가 아니다.

# 8. 독립 풀이·품질감사 인계용 프롬프트

아래를 보내기 **전에** 조정자가 실제 문제 전용 경로·해시·ID·보고서 전용 경로·금지 경로 목록과 예산 기록을 붙여야 한다. 값이 없는 상태로 위임하지 않는다. 답지 경로는 처음에는 금지 목록에만 두며 본문/답 내용은 전달하지 않는다.

```text
정보 A/1~25,B/1~25 독립 풀이 및 고정 후 품질감사를 담당한다.
설치된 네이티브 역할과 실제 gpt-6-astra 실행을 확인하라.
허용/금지 입력·단위·출력 소유권·예산은 조정자가 첨부한 실측 명세만 따른다.
제품·자의 기준·원장 수정과 자식 위임은 금지한다.

1. 문제 전용 입력으로 각 문항을 독립적으로 풀고 조건 충분성과 답을 확인한다.
   실제 최단 풀이, 필수 발상, 쉬운 우회 경로를 같은 표에 기록한다.
   답·작성자 해설·설계표를 읽지 않은 상태에서 전수 답안을 고정한다.
2. 고정·해시 확인 뒤 별도 허용된 답지와 비교 자료를 읽는다.
   정답/해설/채점/범위/신규성/최고 난도+사고력을 각각 판정한다.
   반복 계산·설명 문장 수·반례라는 발문 형식을 고난도로 세지 않는다.
   전 문항 최고 요구를 평균 또는 쉬운 사다리로 대체하지 않는다.
3. 기존 전수 표에 ID별 근거와 수정 방향을 반환하고 한 수정 목록으로 통합한다.
   기대/관측/누락/추가/중복 ID, 실제 읽은 자료·버전·모델, 제한된 검증 범위를 기록한다.
   자료 미확인은 합격이 아니다. 잠정 오류가 반박되면 최종 반환에서 정정하라.
4. 변경하지 않은 근거 재검사나 무관한 원천 전수 탐색으로 내용 검토를 지연시키지 마라.
   실제 자원 실패 시 완료 ID와 재개점만 보존하고 자동 재시도·장시간 대기는 하지 마라.
5. 이 역할의 완료를 전체 배포 승인으로 표시하지 말고 작성·통합 컨텍스트로 반환하라.
```

**계획서 작성의 종료 조건:** 본 파일 저장과 참조·필수 구성 확인. 문항 생성 실행은 이 계획서 작성과 별개이며, 본 파일만으로 문항 품질 또는 재발 방지가 입증된 것은 아니다.
