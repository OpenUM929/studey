**(2) closure 수치는 정정이 필요하다.** 패킷의 `reproduce:` 명령을 그대로 실행:

```
grep "260901" analysis/REV_LOG.md | grep -o '[0-9a-f]{16}' | wc -l          →  43   (패킷: 32)
```

(위 명령의 `{16}`은 셸에서 `\{16\}`로 이스케이프해 실행했다.)

두 가지가 나온다.

- **분자 정정**: `d1e6f5…`는 6자리라 `[0-9a-f]\{16\}` 모집단에 **애초에 들어가지 않는다**(실측 0회).
  따라서 「32개 리터럴 중 오기」는 **3이 아니라 2**다. 세 번째 결함은 실재하지만 다른 모집단
  (16-hex가 아닌 잘린 값 인용)에 속한다. **정정: `2/32` + 모집단 밖 별건 1건.**
  판정에 영향은 없다 — 조항이 잡는 실패는 여전히 3건이다.
- **분모 드리프트**: 패킷이 인용한 `32/19/9`는 **자기 자신의 REV_LOG 행이 추가되기 전** 값이다.
  그 행이 추가되면서 모집단은 `43/21/10`이 됐다. 즉 **패킷은 E3가 금지하려는 바로 그 오류를
  E3의 근거 수치에서 저질렀다.** 이것은 E3에 대한 반증이 아니라 **가장 강한 실증**이며,
  동시에 조항의 문안이 **자기참조 모집단을 다루지 못한다**는 것을 보여준다(→ E3-C1).

| 측정 방법 | 행 수 | sha256 앞16 | 판정 |
|---|---|---|---|
| **동결 명령 그 자체**(`awk` 2회 + 각 `sed '$d'`) | **68** | **`a204f3412cf900b5`** | 판정 `260831_05` 동결값과 **불변 일치** — 자는 온전하다 |
| `sed '$d'` 생략한 단일 awk 2범위 | 70 | `e4423614da073c51` | 패킷 자기신고값과 일치. **거짓 불일치** |
| `sed -n '1,68p'` (행 수만 맞춘 대체) | 68 | `f95e9e2c3dce865c` | **거짓 불일치**. 행 수가 같아도 범위가 다르면 값이 다르다 |

세 값이 모두 다르다는 것이 「명령이 다르면 값도 다르다 — 동결값은 동결 명령 그 자체로 잰다」의
직접 증거다. `type-proposer`가 슬라이스 2에서 「지문 불일치」를 보고한 경로가 세 번째 행이며,
**자가 바뀐 것이 아니라 자를 다른 자로 잰 것**이었다. 조항이 이 오보를 차단한다.

### E1 → **approve. `wc -l` 부가를 승인한다. 조건 1건.**

**승인 근거.** 첫째, 결함이 실재한다 — 동결형은 exit code를 판정 신호로 읽는 순간 3개 상태

8종·`GATEQ` 리터럴이 byte-identical이므로 통과 조건이 넓어지지 않는다. 260828 F6·F9가 명명한
「만족 불가능한 기준을 우회 산출물이나 눈금 손질로 해소」와 **방향이 반대**다. 셋째, 원칙 11이
「도구가 문제를 발견하고도 통과를 반환하면 도구를 먼저 고치라」고 **명령**하므로, 상신만 하고
방치하는 것은 그 자체로 규정 위반이다.

**조건 E1-C1 (구속).** 확정 수용기준을 다시 적을 때 `wc -l` 하나로 끝내지 않는다.
**모집단 하한 절을 함께 적는다.** 근거는 추정이 아니라 실측이다 — 모집단이 없는 상태에서
제안형은 `0` + exit 0을 반환해 **통과를 선언한다**(§1-2 세 번째 행). 원칙 11은 수용기준을
`명령 + 기대 출력 문자열 + 경고 0줄 + 기대 카운트`로 적으라 했고, 「기대 카운트」에는
**무엇을 재고 있는지에 대한 카운트**가 포함돼야 한다.

확정 문안(이것이 새 동결본이다. E1-C1 반영 시 U6 수용기준을 아래로 대체한다):

```
ALLOW='_09_extractor_fix_request|_12_tier2_round2_briefing|_13_arbiter_decision_request|_14_K1_band_measurement'
HIST='정정 이력|철회|종전|오기|최초안|기각|이 자리에 있던|적었다'
GATEQ="grep -rn -e '선택(단답)형'"
POP=$(ls output/260831/260831_*.md 2>/dev/null | wc -l)
RES=$(grep -rn -e '선택(단답)형' -e '60\.4' -e '서답형 비중 50% 초과 회차는 제외' output/260831/260831_*.md 2>/dev/null \
      | grep -vE "$ALLOW" | grep -vF "$GATEQ" | grep -vE "$HIST" | wc -l)
echo "pop=$POP residual=$RES"
[ "$POP" -ge 28 ] && [ "$RES" -eq 0 ] && echo "GATE=PASS" || { echo "GATE=FAIL"; exit 1; }
```

- **기대 출력 문자열**: `pop=28 residual=0` 에 이어 `GATE=PASS` (`pop`은 28 이상이면 가함).
- **기대 카운트**: `RES` = **0**, `POP` = **28 이상**(260902 실측 28. 모집단이 append-only이므로
  하한은 단조 안전하다. 총 매칭 건수에는 여전히 기대값을 두지 않는다 — U6 판단 유지).
- **경고 0줄** + **exit 0**. exit code 단독은 판정 신호가 아니다.
- **동결 유지**: 허용목록 4파일·이력 표식 8종·`GATEQ` 리터럴은 **불변**이며 늘어나면 그 자체가
  결함이다(U6 판단 유지). `POP` 하한 28은 **새로 동결되는 값**이고, 낮추는 것은 자를 넓히는
  변경이므로 새 two-key 라운드가 필요하다.
- **fixture(원칙 12-d)**: §1-2의 3상태. 이 기준은 3/3을 정분류하고 `undetected=0`이다.
  잡아내는 알려진 실패 — (i) 동결형의 exit 반전(패킷이 지목, 이 라운드 재현)
  (ii) 모집단 부재 시 vacuous pass(이 라운드 실측).

**현 상태는 이 기준으로 게이트 통과다** — 실 repo 읽기 전용 실행 결과 `pop=28 residual=0`.

```
B=$(grep -rn "열 축 보류"   output/260831/260831_01_*.md | wc -l)     # 기대: 0
```

> **기입할 값은 그 편집이 끝난 뒤 다시 측정한다.** 편집 전에 잰 값을 편집 후 문서에 옮겨 적으면

> **모집단에 이 문서 자신이나 이 문서가 만들 원장 행이 포함되면, 숫자만 적지 말고 측정 경계를

> 제외한 시점의 값」. 자기참조 모집단에서 맨 숫자는 재현되지 않는다(260902 실측 3/3 드리프트).
