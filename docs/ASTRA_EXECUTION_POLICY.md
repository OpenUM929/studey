# Astra 단독 운영 특칙 — 260910

근거: 사용자 「모든 팀은 해체… ASTRA가 단독으로 처리… 검토 및 감사에 SOL이 존재해서는 안됨」.

## 현재 운영
- 기본 실행은 `gpt-6-astra` 단독이다. 기존 팀 발주와 자동 재개를 중단한다. 종료된 팀/에이전트 기록은 증거로 보존하며 삭제하지 않는다.
- 기존 Sol 팀 배정표, 실험용 assessment-*-sol 레인, 외부 Opus 필수 및 Astra 서브에이전트 의무 규정은 현재 운영의 선행조건이 아니다. 과거 실험 설명은 과거 기록으로만 사용한다.
- 실행 모델은 호스트가 제공한 증거로 확인한다. 요청값·설정 파일을 실제 실행 모델 증거로 표시하지 않는다. 확인 불가 시 이를 명시하고 Astra 실행/감사 완료를 주장하지 않는다.
- 검토·감사·맹목 풀이·최종 판정은 **Astra 전용**이다. Sol은 이 업무에 참여하거나 감사 근거·승인 결론을 제공할 수 없다.
- 단독 실행의 자기검산은 자기검산이다. 답·해설 또는 작성자 결론을 이미 읽은 컨텍스트를 맹목/독립 감사라고 표시하지 않는다. 독립성이 필요한 단계는 팀 병렬 운영이 아닌 별도의 깨끗한 Astra 컨텍스트에서 순차 수행하며, 허용/금지 입력·실제 읽은 파일·해시·문항 ID·결과를 기록한다.

## 성능 부족 시 검토 가능한 대안 — 현재 미승인
- 실제 성능 부족 증거를 제시한 뒤 사용자 결정으로만 `Astra 팀장 + Sol 팀원` 구조를 검토한다. 자동 발주나 재활성화는 금지한다.
- Sol의 허용 후보 업무는 작성·전사·도구 구현 등 비감사 보조뿐이다. 검토·감사·맹목 풀이·판정·배포 승인에는 Sol을 배정하지 않는다.

## 배포 승인
- 모델 정책 변경만으로 문제를 배포 승인하지 않는다. 전수 ID 대조, 정답 및 해설 검증, 범위·자료 근거, 숫자/풀이 유사성, 난이도 및 수정 후 재검증의 기존 기준은 유지한다.
- 최종 판정 근거와 전수 커버리지가 확보된 뒤 문제지·답지/해설을 분리하고 정본·완료 위치·인덱스·감사 이력을 함께 갱신한다. 미충족 항목은 `검토필요`/`▲ blocked`로 남긴다.
- append-only, 작성/감사 분리, 자의 two-key 규칙은 유지한다. 자의 정본 대상은 `analysis/REV_GUIDE.md` §5를 따른다. 이 문서는 자의 수용기준이나 기존 판정을 변경하지 않는다.

이 특칙은 저장소의 과거 모델 배정 및 팀 필수 서술보다 우선한다. Claude Code 역할 파일의 `model: opus/sonnet`은 외부 CLI용 메타데이터이며 Codex 실행 모델 지정으로 해석하지 않는다. `.codex`의 Sol 레인은 삭제/위장 변경하지 않고 현재 운영에서 비활성 취급한다.
