사용자 요청(2026-09-11): 세션 유지·새 독립 세션·기존 작성 세션 복귀·새 이어쓰기 세션을 정확히 안내한다. 이 규약은 권한/독립성/two-key/배포 기준을 변경하지 않는다.

## 기본 원칙
- 한 세션에서 가능한 작성·수정·시험·증거 수집은 승인된 범위 내에서 묶어 계속한다. 중간 산출물 생성만으로 사용자에게 재개 요청이나 세션 이동을 요구하지 않는다.
- 승인된 명세를 반복 작성하거나 부분 후보마다 독립 판정을 요청하지 않는다. 전체 검토 가능한 묶음을 준비한 뒤 실제 독립성·권한 경계에서만 전환한다.
- 현재 응답 종료, 현재 역할 완료, 전체 과업 완료를 구별한다. 호스트 세션을 종료하거나 새 세션을 열지 않았으면 그렇게 했다고 말하지 않는다.

## 목적지 결정표
| 상황 | Session 표시 | 행동과 종료 조건 |
|---|---|---|
| 같은 작성 책임의 후속 작업·시험이 가능 | STAY — 현재 세션 계속 | 현재 세션에서 자동 진행. 단순 부분 완료를 이동 이유로 삼지 않음 |
| 작성 결과에 독립 감사·판정 또는 맹목 풀이 필요 | NEW-INDEPENDENT — 새 독립 세션 | 기존 작성 컨텍스트 재사용 금지. 깨끗한 Astra 컨텍스트에 허용 입력만 제공; 맹목 풀이에는 답·해설·작성자 결론 금지. 독립 산출물을 저장하고 그 역할만 종료 |
| 독립 단계가 끝나고 작성·수정·통합 필요, 작성 세션 사용 가능 | RETURN-AUTHOR — 기존 작성 세션 복귀 | 복귀할 세션의 확인된 식별자/이름 및 소유 WIP를 지정. 작성 세션이 회신 파일을 읽고 허용 범위를 검증한 뒤 승인분만 수행. 판정 세션은 자기가 검토한 결과를 직접 고치지 않음 |
| 작성 세션 복구 불가 또는 컨텍스트/자원 한계로 이어쓰기 필요 | NEW-CONTINUATION — 새 이어쓰기 세션 | 동일 작성 책임의 승계임을 명시. 완료 산출물을 재작성하지 않고 체크포인트 NEXT부터 재개. 독립 감사로 표시하지 않음 |
| 권한/사용자 결정/자원 회복이 실제로 필요 | HOLD — 필요한 조건 명시 | 누가 무엇을 제공해야 하는지, 자동 재개 가능 여부, 정확한 재개 지점을 안내. 새 세션만 만들면 해결된다고 오도하지 않음 |

## 모든 전환 안내에 필수
기존 Pipeline/Stage/Team/Next 4줄은 유지하고, 바로 뒤에 `Session:` 행을 붙인다. STAY면 한 줄이면 충분하다. 실제 전환이면 다음을 빠짐없이 제공한다.
1. 현재 세션의 역할·완료 범위·미완료 범위와 이동 이유.
2. 목적지 종류, 확인 가능한 기존 세션 식별자/이름. 알 수 없으면 미확인으로 표시하고 소유 WIP·작업명으로 찾는 방법을 준다. 식별자는 권한 증명이 아니다.
3. 허용/금지 입력, 산출물 경로, 확인된 입력 해시, 다음 실행/검증 명령, 쓰기 소유권, 중단 조건을 담은 복사 가능한 실행 프롬프트. 기존 회람/예산 규칙을 대체하지 않는다.
4. 완료 후 돌아갈 작성 세션 또는 새 이어쓰기 세션, 읽을 회신 경로, 붙여 넣을 복귀 메시지를 명시한다. 사용자가 다음 목적지를 추측하게 두지 않는다.
5. 새 이어쓰기 세션은 입력·산출물 해시/독점 소유/충돌 쓰기/승인 범위를 재확인하고 NEXT부터 수행한다. 새 독립 세션은 별도 입력 경계를 먼저 확인한다.

## 완료 보고 문구
- 판정 완료: “이 독립 판정 역할은 완료. 전체 배포는 미완료. 작성 세션으로 복귀하여 회신 파일을 읽고 승인된 다음 작업 수행.”
- 이어쓰기: “이 세션의 체크포인트 저장 완료. 과업 미완료. 새 작성 세션에서 지정 WIP의 NEXT 재개.”
- 전체 완료: 산출물 동기화와 최종 검증 증거가 모두 있을 때만 사용.
