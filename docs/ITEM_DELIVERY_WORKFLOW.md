# 문항 완성 우선 실행 절차 — 260912

사용자 지시: 불필요한 검사를 제거하고 세트 전체를 2~3라운드 안에 작성·감사·수정한다.
이 절차는 **기존 유형을 활용하는 문항 생성·배포 작업**의 작업 순서와 분할 방식에 우선한다.
신규 코퍼스 정제·유형 등록·자의 수용기준 변경 절차에는 적용하지 않는다.
모델은 `docs/ASTRA_EXECUTION_POLICY.md`, 보호 대상은 `analysis/REV_GUIDE.md` §5를 따른다.

## 1. 세트 단위 2~3라운드

- **1라운드 — 전체 작성과 전체 내용 감사.** 유형·범위 자료를 한 번 확인하고 전체 문항, 답·해설, 채점 기준, 비수치 변형 근거를 작성한다. 작성자는 정답·조건·선지 우회·자료 필요성을 먼저 자기검산한다. 깨끗한 Astra 컨텍스트의 맹목 풀이를 전 문항에 수행하고, 독립 답을 고정한 뒤 답·해설 대조 및 신규성·범위·난도 감사를 완료한다. 역할별 입력 격리와 작성/감사/판정 분리는 유지하되 발견 사항은 세트 전체의 단일 수정 목록으로 모은다. 앞 문항의 난도 지적 때문에 뒤 문항의 첫 검토를 막지 않는다.
- **2라운드 — 일괄 수정과 영향 범위 재검증.** 작성자가 승인 범위의 차단 결함을 한 번에 수정한다. 독립 검토자는 변경 문항과 공유 지문·정답표·배점 등 영향을 받는 부분을 재검증한다. 변경되지 않은 문항은 입력 버전과 적용 기준이 같음을 확인해 기존 증거를 재사용한다. 전체 ID 대조와 최종 문제·답·해설 내용 동기화를 확인하고 최종 판정에 따라 배포본을 만든다.
- **3라운드 — 남은 내용 결함만 종결.** 새로운 취향·문체 개선은 추가하지 않는다. 남은 오류와 수정으로 생긴 회귀만 처리한다. 종료 시 차단 결함이 남으면 통과로 만들지 않고 `▲ blocked`로 보존하며, 같은 미세 수정 루프를 4라운드로 연장하지 않는다. 실패 원인을 근거로 관련 생성·감사·배포 지침 전체의 충돌과 불필요 절차를 재감사하고 재설계한다. 보호 기준을 낮추거나 라운드 번호를 초기화해 실패를 숨기지 않는다.

라운드는 **전체 세트의 작성/수정 → 감사 → 지적 통합** 한 주기다. 호출·슬라이스 수는 별도로 기록한다. 체크포인트는 저장 단위일 뿐 별도 승인·발주·세션 전환 단위가 아니다. 자원 한계가 실제로 필요할 때만 분할하고, 완료분을 재수행하지 않는다. 소규모 세트 자체를 유계 단위로 삼을 수 있으며 8~10문항 분할이나 G0~G8의 1~2개씩 발주는 기본값이 아니다.

3라운드 실패 시 지침 전체의 관련성을 점검하되, 실제 절차 원인이 확인된 충돌 지침만 한 번에 수정한다. 개별 내용 결함은 해당 문항과 영향 범위에 한정하며, 지침 감사 자체를 반복 프로젝트로 확대하지 않는다.

## 2. 없애는 반복과 범위 밖 작업

- 이미 있는 유형 분석을 사용하면서 HWP 재변환·재전사·재분류를 시작하지 않는다. 자료 공백은 해당 근거 주장에 한정하여 기록하고 정본 ID를 날조하지 않는다.
- 문항 내용과 무관한 A4 용지·여백·인쇄·미관 검사는 요청이 없으면 수행하지 않는다. **품질감사 항목명 A4(서술형 채점 기준)**는 용지 A4와 다르며 삭제하지 않는다.
- 문항만 바뀌었는데 저장소 전역 시스템 감사·모델 정책 재검토·변하지 않은 원자료 전수 재해시를 반복하지 않는다. 해당 변경의 영향 범위 검사만 실행한다.
- 같은 파일·버전의 같은 증거를 여러 보고서에 복사하지 않는다. WIP는 위치·진행 확인에만 사용하며, 판정 증거는 기존 감사 보고서와 그 입력/산출물 해시·ID를 직접 참조한다. append-only 이력은 삭제하지 않는다.
- 명확한 내용 수정·재검증·배포 요청에 자잘한 재승인을 요구하지 않는다. 독립 감사 컨텍스트는 내부에서 마련할 수 있으면 마련하고 사용자에게 세션 이동을 떠넘기지 않는다.
- 경계 난도에 대한 취향 차이, 단순 문체, 비차단 권고를 새 수정 라운드의 이유로 삼지 않는다. 난도 표기가 실제보다 높으면 기준을 고치는 대신 정확히 재표기하되 요구된 최고 난도·배점 조건은 유지한다.

## 2-a. 승인 뒤 실제 실행 — 중간 응답으로 멈추지 않기

- **승인 수령 후 같은 턴에서 실행한다.** 앞서 제시한 결정 묶음에 동의한 답변은 그 범위만 작성 조정자의 소유 WIP 또는 결정 기록에 한 번 기록하고 다음 안전한 작업을 수행한다. “이어서 하겠다”는 약속만으로 종료하거나 같은 선택을 이름만 바꿔 재요청하지 않는다. 방향 승인은 정확한 기준 변경·독립 감사키·배포 승인으로 확대하지 않는다.
- **차단 범위를 명시한다.** 막힌 판정·보호 파일 반영·배포와 현재 허용된 근거 정리·수정 제안을 구별한다. 기존 판정이 허용한 실질 작업이 남으면 계속한다. 별도 제안본도 기존 판정의 허용 범위 안에서만 준비하며, 명시된 제품 쓰기 금지를 우회하지 않는다. 제안본을 승인 정본·독립 검증본으로 표시하지 않는다.
- **보고서는 실질 결과를 담는다.** 새 문항 내용·새 근거·새 검증 결과·실제 미결 결정 없이 같은 NEXT를 다른 파일로 옮기지 않는다. 재개 때 한 번 확인한 불변 입력을 매 응답마다 재해시하지 않는다. 지침 수정·승인 수령·보고서 저장 자체는 문항 작업 종료 사유가 아니다.
- **독립 단계의 실행 가능성을 실제로 확인한다.** 저장소 발주 규칙과 예산 확인을 지키며 깨끗한 Astra 컨텍스트에서 순차 수행한다. 요청 모델과 실제 모델이 다르면 그 반환을 감사·판정 근거에서 배제한다. 용량/쿼터 실패 시 추가 호출·모델 교체·재시도 분산 없이 현재 유계 작업의 안전한 저장만 마치고 자원 체크포인트로 이어간다. 자기검산을 독립 감사로 대체하지 않는다.
- **종료와 예측을 구별한다.** 시간 질문에는 실제 완료 내용과 남은 독립 단계, 측정 가능한 소요와 불확실성을 답한다. 근거 없는 완료 시각은 약속하지 않는다. 완료 또는 실제 사용자 결정·권한·필수 입력·자원 차단일 때만 중단하며, 미완료 상태와 정확한 재개 위치를 남긴다.

## 2-b. 260912 실패 재발 방지 — 내용 우선·최단 풀이 확인

이 절은 기존 난도·신규성 기준의 적용 순서를 보완한다. 새로운 Tier 눈금·합격 기준·독립 승인 단계는 만들지 않는다.

- **출제 전에 이미 확보한 유형 분석을 사용한다.** 문항마다 기존 설계/답지에 근거 유형과 비수치 변형, 학생의 가장 짧은 타당한 풀이, 반드시 필요한 발상을 간결히 적는다. 작성자의 긴 모범풀이 대신 더 쉬운 풀이·선지 우회·작은 경우의 단순 열거로 끝나는지 먼저 확인한다. 유형 분석을 다시 만드는 별도 프로젝트로 돌리지 않는다.
- **쉬운 설계의 대량 복제를 먼저 막는다.** 첫 대표 문항을 작성하는 즉시 작성자 스스로 요구 난도와 최단 풀이를 대조한다. 미달한 생성 방식은 나머지에 확장하기 전에 고친다. 이는 기존 작성 라운드 안의 자기검산이며 별도 보고서·서브에이전트 호출·사용자 승인 대기 단계가 아니다. 이미 작성한 세트의 나머지 문항 감사는 중단하지 않는다.
- **형식적인 사고력 보강은 고난도 근거가 아니다.** 기존 코드/지문에 ‘설명·증명·반례를 쓰시오’를 붙이거나 숫자·반복 횟수·문자 변수를 늘린 것만으로 최상위라고 표시하지 않는다. 발문에 핵심 발상·반례·경우 분류를 알려 주어 요구 사고를 없애지 않았는지 확인한다. 조건의 개수만 늘려도 합격이 아니다. 조건·자료가 실제로 풀이에서 함께 필요하고 기존 기준에 맞는 발상이 필수인지 검토한다.
- **전 문항 최고 난도 요구를 평균으로 대체하지 않는다.** 해당 요구가 있는 세트는 쉬운 문항을 사다리로 섞거나 일부 어려운 문항으로 나머지를 상쇄하지 않는다. 최고 수준 비교 근거가 없으면 미확인이지 합격이 아니다. 자기검산 결과를 독립 난도 판정으로 표시하지 않는다.
- **정답 일치·감사 완료·품질 합격·배포 승인을 구분한다.** 실행 출력·ID·배점 검사 통과는 그 검사에만 적용한다. 문항별 해설 중간 과정, 유형·원천 근거, 실제 채점 요소는 작성할 때 함께 완성하고 범용 채점 문장 복제로 대체하지 않는다. 수정 후 상태를 확인하지 않고 이미 고친 결함을 미수정이라고 반복 보고하거나, 미확인 결함을 확정 오류라고 보고하지 않는다.
- **대기로 사용자의 시간을 소모하지 않는다.** 날짜·시간대·실제 재개 가능성이 확인되지 않은 제한 안내로 장시간 sleep을 호출하지 않는다. 이 문항 작업에서는 사용자가 명시적으로 대기를 요청하지 않는 한 동기식 장시간 대기 대신 기존 자원 체크포인트를 남기고 현재 턴을 종료한다. 새 입력·복구 증거 없이 동일 제한을 반복 조회·재시도하지 않으며 모델 우회도 하지 않는다. 실제로 실행 중인 도구·감사의 결과 회수는 자원 리셋을 기다리는 타이머와 구분한다.
- **말로 재개하거나 라운드를 초기화하지 않는다.** 수행 가능한 승인 작업이 남아 있으면 새 결과 없이 ‘다음에 하겠다’는 최종 응답으로 넘기지 않는다. 반대로 실제 차단이면 원인과 완료분만 정확히 남긴다. 실패 후보·감사 증거를 삭제하거나 ‘새 세트/새 라운드’로 이름만 바꾸어 실패 이력과 2~3라운드 한도를 초기화하지 않는다. 기존 자료와 검증은 보존하고 승인된 수정 범위 안에서 재설계한다.

## 3. 유지하는 내용 검증과 배포 증거

정답의 정확성·유일성, 조건 충분성, 해설 중간 단계, 서술형 채점 가능성, 교육과정·유형 근거, 숫자/단어 치환에 불과하지 않은 구조적 신규성, 세트 내 동형 반복, 최고 난도의 실제 사고 요구를 전 문항에서 검토한다. 최고 난도는 선지 한 개나 암기 문장으로 자료 해석을 우회할 수 없어야 한다.

기대/관측 ID, 누락·추가·중복, 작성자와 독립 검토자 구분, 실제 입력/산출물 버전, 수정 후 재검증, 최종 판정 및 동일 통합본에서 파생한 문제지·답지의 내용 일치는 유지한다. 검사 횟수를 줄이는 것이지 합격 기준·미검증 경고·two-key·append-only를 없애는 것이 아니다. 차단 검사의 경고는 해결 전 통과로 표시하지 않는다. 범위 밖 검사를 생략한 것을 그 검사의 PASS로 기록하지 않는다.

## 4. 현재 과학 25제에 적용

기존 조각별 맹목 검토 5회 호출을 전체 세트 5라운드라고 오기하지 않는다. 기존 증거를 보존하고 남은 내용 감사 결과를 한 번에 통합한다. 기실행 호출을 숨기거나 완료를 소급 선언하지 않으며, 이후 일괄 수정·재검증은 최대 두 주기로 제한한다. 현재는 답·해설 독립 대조와 신규성 전수 감사가 미완료이므로 배포 승인이 아니다.
