**신규 증거**: 원문 도표에서 직선은 A도 B도 지나지 않고 **둘 사이를 가로지르도록** 그려져 있다
(A는 수직 점선, B는 수평 점선으로만 표시). 케이스 ①(개구간, 합 -15) 쪽 근거이나, 도표는 한
예시 위치일 뿐이라 단독으로 경계를 확정하지 못한다 → **근거 (iv)** 로만 추가하고 케이스 ②는
강등하지 않았다(사용자 지시 「두 케이스 모두 저장」 유지).

## 자기 신고
1. **측정 오류(즉시 정정)** — 게이트 1차 실행에서 `EXIT=$?`를 파이프 뒤에 놓아 **grep의 종료코드**를
   읽었다. 원칙 11이 금지하는 「exit code 하나로 통과 선언」보다 나쁜, **틀린 exit code 인용**이다.
   파이프 없이 재측정해 위 값(전부 real EXIT=0)으로 대체했다.
2. **커버리지 한정** — 18장 중 **1장(5.6%)** 만 대조했다. 나머지 17장은 미대조이므로
   `meta.yml confidence`는 `medium` 유지가 맞고, 「전사 검증 완료」로 말할 수 없다.

3. **원장 열 구조 위반(즉시 정정)** — REV_LOG(5열)·`_index`(8열)에 행을 덧붙이면서 **양쪽 다 열 수를 맞추지 않았다.**
   REV_LOG는 날짜를 `2026-09-02`로 적어 기존 `YYMMDD` 관행과 어긋났고, `_index` 행은 6열뿐인 데다 표가 아니라
   **표 뒤 산문 아래**에 붙어 별도 1행 표가 생겼다. 발견 즉시 두 행 모두 규격에 맞게 재작성하고 표 안으로 옮겼다
   (내용 삭제 아님 — 방금 내가 만든 행의 형식 정정). 원인은 붙이기 전에 **헤더 열 정의를 읽지 않은 것**이다.
   규칙: 공유 원장에 append하기 전 `grep -nE '^\|' <원장> | head -3`으로 열 정의를 먼저 읽는다.
