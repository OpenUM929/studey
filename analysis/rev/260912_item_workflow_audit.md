## 수정 계획과 검증
1. 문항 생성 전용 절차를 한 곳에 두고 2~3 세트 라운드·내용 우선·증거 재사용을 명시한다.
2. 공통 지침과 네 실행 역할에서 그 절차를 우선 참조하고 미세 분할 기본값을 제거한다. 과거 원장·사용자 변경과 보호 자는 보존한다.
3. 독립 검토자는 절차의 품질 기준 약화·독립성 훼손·우선순위 충돌만 한 번 검토한다. 수정자는 결과를 반영한다.
4. 기존 textpatch 회귀 시험, 참조 도달 검사, 보호 파일 해시 보존, diff whitespace 검사를 수행한다. 문서 수정에 무관한 앱 빌드·A4 검사는 하지 않는다.

## 독립 검토 발주 범위
단위: 새 절차 1파일과 이 계획 1파일; 허용 입력은 이 두 파일 및 REV_GUIDE §5, Astra 정책, 관련 역할의 해당 절차. 제품/원장 쓰기 금지. 반환 스키마: 심각도/근거 경로/수정 제안/판정, 실제 읽은 파일 및 모델 보고. lane=procedure-review = gpt-6-astra; 요청 깊이 xhigh, 실측 깊이는 노출 여부 그대로 기록. 역할 지침: architect (설계 위험 검토 책임), 제품 승인 권한 없음. 잔여 서비스 예산 미노출=insufficient, fallback2 단일 유계 슬라이스. 최대 동시1, 도구6회 또는 8분에 부분 결과 반환. 재귀 위임 금지. 검증: 두 파일의 직접 검토 결과와 실제 입력 확인; 재개점은 절차의 지적 일괄 반영. 문항 내용 감사/배포 판정은 범위 밖.

## 독립 반환 및 반영
`/root/procedure_review`, fork none, host 모델 gpt-6-astra/실제 깊이 미노출, read-only 3도구 호출. 판정 WATCH, 직접적인 정확성·독립성·two-key 완화 없음. 중간: WIP를 판정 증거로 쓰지 말 것. 낮음: 실패 시 전역 지침 감사의 재귀적 확대 방지. 두 지적을 모두 절차에 반영했다. 반환은 설계 검토이며 문항 배포 승인이 아니다. 읽은 입력 hash16: 계획 79b91ee61549574d, 절차 8d7e06a830ba8749, Astra 정책 40424dd0e82eb362, REV_GUIDE 62641c9f517bb4b4. 이 기록은 리더가 보존한 반환 요약이다.

## 실행 검증
- textpatch self-test: seeded=10 undetected=0, exit 0. FAIL/WARN 출력은 혼합 개행 거부/명시 허용의 의도적 음성 fixture이며 운영 게이트 경고 무시가 아니다.
- 절차 참조 8곳 연결, 보호 자 3파일 SHA256 변경 없음. 배포 역할의 1~2개 게이트 분할 기본 권장을 실제 교체했다.
- 전체 assurance-contract는 exit 1, 11 failures: 타 작업 WIP 형식 8건과 ruler 실행/검출 출력 3건. 이것을 문항 오류나 절차 수정 PASS로 바꾸지 않으며 관련 없는 파일은 고치지 않는다. 수정된 참조·문법은 별도 범위 검사로 확인한다.
- sync_global_continuity_guidance.py는 전역 저장/복귀 블록 설치 도구임을 점검했다. 문항 전용 절차를 전역 설치하지 않으므로 코드 변경 불필요.
