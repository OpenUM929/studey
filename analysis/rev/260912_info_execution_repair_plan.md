## 원인과 경계

현행 `docs/ITEM_DELIVERY_WORKFLOW.md` §2는 이미 재승인·증거 복사를 금지한다. 따라서 이번 재발은 지침 부재만의 문제가 아니라 실행자의 미준수다. Q3에 별도 사용자 선택이 필요한 것 자체는 `output/260911/rev/260911_03_info_ab50_ruler_ruling.md` Q3/Q4에 따른 실제 권한 경계다. 그러나 승인 답변 뒤 실행 도구 없이 “이어가겠다”는 응답으로 끝낸 것은 그 권한 경계로 설명되지 않는다.

수정 대상은 `docs/ITEM_DELIVERY_WORKFLOW.md` §2 다음의 실행 규칙 한 절이다. 보호 자·검사 코드·과거 판정·제품은 이 수정 대상이 아니다. 동반 문서들은 기존 우선 참조의 도달 여부를 검사하며 같은 규칙을 복제하지 않는다.

## 적용할 문구

### 승인 이후 실제 실행과 차단 범위

- **승인 후 실행 의무:** 최신 답변이 앞서 제시한 결정 묶음에 동의한 것이면 그 범위만 기존 WIP/결정 기록에 한 번 남기고, 다음 안전한 실행을 같은 턴에서 수행한다. “진행하겠다”는 약속만으로 턴을 끝내거나 같은 선택을 다른 이름으로 재요청하지 않는다. 기준 방향의 동의는 정확한 기준 변경·독립 감사키·배포 승인으로 확대하지 않는다.
- **차단은 작업별로 분리:** 막힌 판정/보호 파일 반영/배포와 아직 허용된 읽기·근거 정리·수정 제안을 구별한다. 허용된 실질 작업이 남으면 그 작업을 수행한다. 특정 판정이 제품 쓰기를 금지하면 그대로 지키되, 별도 제안본 준비까지 금지됐다고 확대하지 않는다. 제안본은 승인된 정본이나 독립 검증본으로 표시하지 않는다.
- **인계·결정 보고서 재생산 금지:** 새 산출물은 새 문항 내용·새 근거·새 검증 결과 또는 실제 미결 결정이 있을 때만 만든다. 같은 NEXT를 다른 파일로 옮기는 것만으로 진행을 보고하지 않는다. 한 번의 재개 대조 뒤 변하지 않은 입력을 매 응답마다 다시 해시하지 않는다.
- **독립 단계는 내부에서 순차 진행:** 실행 가능 여부와 예산을 확인하고 저장소의 발주 규칙에 따라 깨끗한 Astra 컨텍스트를 사용할 수 있으면 사용한다. 작성/감사 분리, 맹목 입력 제한, 실제 입력·산출물 증거는 유지한다. 실행 불가면 정확한 제한을 기록하며 팀/모델을 몰래 바꾸거나 감사 완료를 꾸미지 않는다.
- **완료 예측과 종료:** 시간 질문에는 새로 완료한 내용, 남은 내용·독립 단계, 현재 실측 가능한 소요/불확실성을 답한다. 근거 없는 완료 시각을 약속하지 않는다. 종료는 완료 또는 실제 사용자 결정/권한/필수 입력/자원 차단이며, 단순 승인 수령·보고서 저장·지침 수정은 작업 중단 사유가 아니다.
